# داشبورد التحصيلات

تطبيق ويب (واجهة ثابتة على GitHub Pages + Firebase للبيانات والدخول والصلاحيات).

## الإعداد (مرة واحدة، حوالي 20 دقيقة)

1. **Firebase:** من console.firebase.google.com أنشئ مشروعاً، ثم Add app > Web، وانسخ الإعدادات داخل `firebase-config.js`.
2. **تسجيل الدخول:** Build > Authentication > Get started > فعّل **Email/Password**.
   (التطبيق يحوّل رقم الموبايل داخلياً إلى `رقم@collections.app` فلا يحتاج رسائل SMS ولا فوترة.)
3. **قاعدة البيانات:** Build > Firestore Database > Create (Production mode).
4. **قواعد الحماية:** تبويب Rules، الصق محتوى `firestore.rules` كاملاً ثم Publish.
5. **GitHub:** أنشئ repository وارفع كل الملفات، ثم Settings > Pages > Deploy from branch (`main`, `/root`).
6. **اعتماد الدومين:** في Firebase: Authentication > Settings > Authorized domains، أضف `USERNAME.github.io`.
7. **أول دخول:** افتح الموقع واضغط «إعداد أول مرة» وأنشئ حساب الأدمن **فوراً**. (أول من ينشئه يصير الأدمن ولا يمكن تكراره.)
8. من تبويب **الإدارة**: اضغط «استيراد» واختر ملف `NOT-FOR-GITHUB/seed.json` من جهازك (لا ترفع هذا المجلد على GitHub)، راجع التارجت، ثم أضف المستخدمين.

## الصلاحيات
- القوالب: مدير فرع، تيلي سيلز، مندوب، محاسب، إدارة (نتائج فقط)، أدمن.
- لكل مستخدم صلاحيات مفصلة: إدخال، مراجعة، نتائج، سجل، إدارة، ونطاق البيانات (الكل أو أسماء/فروع محددة).
- الحماية الفعلية في `firestore.rules` وليست في الواجهة فقط.

## ملاحظات مهمة
- **اختبر القواعد:** لم أستطع تشغيلها على Firebase حقيقي. جرّبها في Rules Playground قبل التشغيل الفعلي، خصوصاً قراءة المستخدمين المحددين بفروع.
- **سجل العمليات** يُكتب من المتصفح، فهو مفيد للمتابعة لكنه ليس مقاوماً للتلاعب من أدمن متمكن. للتدقيق الصارم نضيف Cloud Functions (تحتاج Blaze).
- **نسيان كلمة السر:** غيّرها المستخدم بنفسه من زر «تغيير كلمة السر». إن نسيها يحذف الأدمن حسابه من Firebase Console (Authentication) ثم يضيفه من جديد.
- **مفتاح apiKey** في الواجهة عام بطبيعته، والأمان يعتمد على القواعد.
- البيانات التاريخية مجمّعة شهرياً، والأيام الجديدة تتراكم من الإدخال.
